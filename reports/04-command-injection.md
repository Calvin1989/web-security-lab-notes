\# Web 漏洞复现报告：SQL 注入



\## 1. 漏洞概述



\- 漏洞名称：SQL 注入

\- 漏洞类型：输入验证缺陷 / 注入漏洞

\- 风险等级：高

\- 复现环境：DVWA / Pikachu

\- 测试方式：本地授权靶场测试

\- 影响范围：用户查询、登录认证、数据检索等与数据库交互的功能点。



\## 2. 漏洞原理



SQL 注入漏洞产生的根本原因是服务端将用户输入直接拼接进 SQL 查询语句，未使用参数化查询或预编译语句进行安全处理。



当用户输入能够影响后端 SQL 语句结构时，攻击者可以构造异常输入改变原有查询逻辑，从而造成未授权数据查询、登录绕过、敏感信息泄露，严重情况下还可能导致数据篡改或数据库权限被进一步利用。



\## 3. 复现环境



\- 系统环境：Windows

\- 靶场名称：DVWA / Pikachu

\- 靶场地址：本地地址

\- 使用工具：Burp Suite Community、浏览器

\- 测试账号：本地靶场测试账号

\- 漏洞模块：SQL Injection



\## 4. 复现步骤



\### 4.1 定位测试点



在 DVWA 的 SQL Injection 模块中，页面提供了用户 ID 查询功能。该功能会根据用户输入的 ID 查询数据库中的用户信息。



该输入点与数据库查询逻辑相关，因此可以作为 SQL 注入测试点。



\### 4.2 抓取请求



使用 Burp Suite 代理浏览器请求，访问 SQL Injection 模块并提交正常参数。



重点观察以下内容：



\- 请求方法；

\- 请求 URL；

\- 参数名称；

\- Cookie；

\- 返回状态码；

\- 响应内容变化。



\### 4.3 构造测试输入



在用户 ID 参数中输入正常数字，观察正常返回结果。



随后构造异常输入，观察页面响应是否发生变化，判断用户输入是否影响了后端 SQL 查询逻辑。



\### 4.4 观察响应结果



如果异常输入导致页面返回非预期数据、报错信息或响应内容发生明显变化，则说明该参数可能存在 SQL 注入风险。

\## 6. 风险影响



SQL 注入漏洞可能造成以下影响：



\- 未授权查询数据库内容；

\- 敏感用户信息泄露；

\- 绕过登录认证；

\- 篡改或删除数据库数据；

\- 在高权限数据库账户场景下，可能进一步影响服务器安全。



\## 7. 修复建议



建议从以下方面进行修复：



1\. 使用参数化查询或预编译语句，避免用户输入直接拼接 SQL 语句；

2\. 对用户输入进行白名单校验，例如 ID 参数只允许数字；

3\. 关闭生产环境中的详细 SQL 错误回显；

4\. 数据库账号应遵循最小权限原则；

5\. 对异常查询行为记录安全日志并进行告警；

6\. 前端校验只能提升用户体验，不能作为主要安全防护措施。
