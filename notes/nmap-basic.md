# Nmap 基础使用备忘

## 1. 文档说明

本文档记录本项目中使用 Nmap 进行本地靶场服务识别和端口探测的基础命令。内容面向安全评估入门场景，用于配合 DVWA、Pikachu 等本地授权环境完成资产识别、Web 服务确认和报告证据整理。

Nmap 在本项目中的定位是辅助工具：

- 识别本机或实验网段中开放的端口；
- 判断 Web 服务是否可访问；
- 辅助确认服务类型和基础版本信息；
- 为后续 Burp、dirsearch、SQLmap、Nuclei 等验证提供目标范围；
- 形成安全评估报告中的“测试范围”和“工具辅助评估”证据。

## 2. 基本原则

使用 Nmap 前先确认测试范围：

- 只扫描本机、实验靶场或明确授权的目标；
- 不扫描公网陌生 IP；
- 不进行高强度、破坏性或绕过类扫描；
- 报告中写清楚扫描目标、命令、时间和结论；
- 扫描结果需要人工复核，不能直接把工具输出当成最终漏洞结论。

## 3. 常用目标写法

```powershell
nmap 127.0.0.1
nmap localhost
nmap 192.168.56.101
nmap 192.168.56.0/24
```

常见本地靶场目标可能是：

```text
127.0.0.1
localhost
192.168.x.x
10.0.2.x
```

具体地址应以本机 Docker、虚拟机或实验环境配置为准。

## 4. 常用扫描命令

### 4.1 基础端口扫描

```powershell
nmap 127.0.0.1
```

用途：快速查看目标开放了哪些常见端口。

### 4.2 指定端口扫描

```powershell
nmap -p 80,443,8080 127.0.0.1
```

用途：只检查 Web 相关端口，减少无关输出。

### 4.3 全端口扫描

```powershell
nmap -p- 127.0.0.1
```

用途：检查所有 TCP 端口。实验环境可用，但真实环境中要注意授权和扫描强度。

### 4.4 服务版本识别

```powershell
nmap -sV -p 80,8080 127.0.0.1
```

用途：识别端口背后的服务类型和版本信息。

### 4.5 默认脚本扫描

```powershell
nmap -sC -sV -p 80,8080 127.0.0.1
```

用途：执行默认 NSE 脚本并识别服务版本。适合本地靶场辅助评估，不应在未授权目标上随意执行。

### 4.6 操作系统识别

```powershell
nmap -O 127.0.0.1
```

用途：尝试识别操作系统。结果可能不准确，需要结合环境信息判断。

### 4.7 跳过主机发现

```powershell
nmap -Pn 127.0.0.1
```

用途：目标禁 ping 或主机发现不稳定时，直接进行端口扫描。

### 4.8 输出结果到文件

```powershell
nmap -sV -p 80,8080 -oN scan-results/nmap/http-baseline.txt 127.0.0.1
```

用途：保存普通文本结果，便于后续写报告和留存证据。

## 5. Web 服务识别示例

### 5.1 识别 HTTP 标题

```powershell
nmap --script http-title -p 80,8080 127.0.0.1
```

关注输出中的：

- `http-title`；
- Web 应用标题；
- 默认页面；
- 是否暴露管理后台或靶场页面。

### 5.2 基础 HTTP 信息

```powershell
nmap --script http-headers -p 80,8080 127.0.0.1
```

关注输出中的：

- `Server`；
- `X-Powered-By`；
- 安全响应头是否缺失；
- 是否暴露过多服务信息。

### 5.3 常见 Web 端口

```powershell
nmap -sV -p 80,443,8000,8080,8081,8888 127.0.0.1
```

适合快速确认本地 Web 靶场运行在哪个端口。

## 6. 结果解读要点

| 字段 | 说明 |
|---|---|
| PORT | 端口号和协议，例如 `80/tcp` |
| STATE | 端口状态，例如 `open`、`closed`、`filtered` |
| SERVICE | 服务类型，例如 `http`、`mysql`、`ssh` |
| VERSION | 版本识别结果，可能不完全准确 |
| SCRIPT | NSE 脚本输出，需要人工判断含义 |

常见判断：

- `open`：端口开放，后续可继续确认服务；
- `closed`：目标可达，但端口未开放；
- `filtered`：可能被防火墙过滤，不能直接判断服务不存在；
- 服务版本识别结果只作为线索，不等于漏洞确认。

## 7. 本项目中的典型流程

```text
1. 使用 nmap 确认本地靶场 Web 端口
2. 使用 -sV 识别服务类型
3. 使用 http-title / http-headers 辅助确认 Web 页面和响应头
4. 使用浏览器访问目标页面
5. 使用 Burp 抓取关键请求
6. 使用 dirsearch / SQLmap / Nuclei 做辅助验证
7. 人工复核工具结果
8. 将有效证据整理进报告
```

Nmap 负责“确认目标和服务面”，Burp 负责“验证请求和漏洞证据”，二者不要混淆。

## 8. 示例记录格式

报告中可以这样记录：

```text
工具：Nmap
目标：127.0.0.1
命令：nmap -sV -p 80,8080 127.0.0.1
结论：目标开放 Web 服务端口，后续使用浏览器和 Burp 对 DVWA / Pikachu 页面进行人工验证。
备注：扫描仅限本地授权靶场，结果仅作为服务识别和测试范围确认依据。
```

## 9. 常见排错

| 问题 | 排查方向 |
|---|---|
| 未发现端口 | 确认靶场是否启动、端口映射是否正确 |
| 目标不可达 | 检查 IP、Docker 网络、虚拟机网卡和防火墙 |
| 版本识别为空 | 尝试增加 `-sV` 或指定端口 |
| HTTP 标题为空 | 页面可能需要访问具体路径，或服务不是 HTTP |
| 扫描结果很多 | 使用 `-p` 限定端口范围 |
| 报告证据不清楚 | 保存 `-oN` 文本结果并补充截图 |

## 10. 安全声明

本项目中的 Nmap 命令仅用于本地授权靶场和学习环境。任何端口扫描都应遵守授权边界，不对未知公网目标、第三方系统或未授权资产执行扫描。
