# Web 攻击日志表现与告警建议速查表

## 1. 文档说明

本文档用于总结常见 Web 漏洞在访问日志、安全设备日志和应用日志中的可能表现，并给出基础告警建议。

本项目中的漏洞复现均在 DVWA、Pikachu 等本地授权靶场中完成。本文档仅用于安全学习、日志分析思路整理和安全运营能力训练，不涉及真实目标攻击或未授权测试。

本文档关注的重点是：

- 漏洞复现行为在日志中可能长什么样；
- 安全运营人员如何从日志中发现异常；
- 如何降低误报；
- 如何将漏洞复现与日志告警分析联系起来。

## 2. 日志分析基础字段

分析 Web 攻击日志时，常用字段包括：

| 字段 | 说明 |
|---|---|
| 源 IP | 发起请求的客户端 IP |
| 请求时间 | 请求发生时间 |
| HTTP 方法 | GET、POST、PUT 等 |
| URI 路径 | 被访问的接口或页面路径 |
| Query 参数 | URL 中的参数内容 |
| 请求体 | POST 表单、JSON、文件上传内容 |
| User-Agent | 客户端浏览器或工具标识 |
| Cookie | 会话标识和安全等级等信息 |
| 状态码 | 200、302、403、404、500 等 |
| 响应大小 | 响应内容长度 |
| Referer | 请求来源页面 |
| 账号标识 | 登录账号、用户 ID、用户名等 |
| 处理耗时 | 请求响应耗时 |

单个字段通常不能直接证明攻击行为，实际研判时应结合多个字段进行关联分析。

## 3. SQL 注入日志表现

### 3.1 常见日志特征

SQL 注入测试在日志中可能出现以下特征：

- 参数中出现单引号；
- 参数中出现 `OR`、`AND`、`UNION`、`SELECT`、`SLEEP`、`DATABASE` 等 SQL 关键字；
- 参数中出现注释符，例如 `--`、`#`、`/* */`；
- 参数中出现 URL 编码后的特殊字符，例如 `%27`、`%23`、`%2D%2D`；
- 同一 IP 短时间内对同一参数反复测试；
- 响应状态码出现 500；
- 响应长度与正常请求差异明显。

### 3.2 示例特征

```text
/dvwa/vulnerabilities/sqli/?id=1%27+OR+%271%27%3D%271&Submit=Submit
```

其中 `%27` 是单引号的 URL 编码，整体含义接近：

```text
1' OR '1'='1
```

### 3.3 告警建议

- 对包含 SQL 关键字和特殊字符组合的请求进行告警；
- 对同一 IP 高频访问同一参数的行为进行聚合分析；
- 结合 500 状态码、响应大小变化和请求频率降低误报；
- 对登录、查询、订单、用户信息等敏感接口提高告警等级。

### 3.4 误报控制

单独出现 `select`、`union` 等英文单词不一定是攻击，需要结合上下文判断。比如搜索框中用户搜索数据库教程时也可能出现 SQL 关键词。因此建议结合参数位置、特殊字符组合、访问频率和响应异常共同判断。

## 4. XSS 日志表现

### 4.1 常见日志特征

XSS 测试在日志中可能出现以下特征：

- 参数中出现 `<script>`；
- 参数中出现 `alert`、`prompt`、`confirm` 等 JavaScript 关键字；
- 参数中出现事件属性，例如 `onerror`、`onload`、`onclick`；
- 参数中出现 HTML 标签，例如 `<img>`、`<svg>`、`<iframe>`；
- 参数中出现 URL 编码后的脚本内容，例如 `%3Cscript%3E`；
- 留言、评论、昵称、搜索等输入点出现脚本标签。

### 4.2 示例特征

```text
/dvwa/vulnerabilities/xss_r/?name=%3Cscript%3Ealert%28%27xss%27%29%3C%2Fscript%3E
```

解码后为：

```html
<script>alert('xss')</script>
```

### 4.3 告警建议

- 对 `<script>`、`%3Cscript%3E` 等明显脚本标签进行告警；
- 对事件属性和危险标签进行中低危告警；
- 对评论、留言、后台公告等存储型输入点提高告警等级；
- 结合访问路径判断是否属于用户输入回显功能。

### 4.4 误报控制

部分业务可能允许富文本输入，例如文章编辑器、后台公告、Markdown 编辑器等。此类场景需要结合业务白名单和服务端 HTML 清洗策略判断，不能仅凭 HTML 标签就判定为攻击。

## 5. 文件上传漏洞日志表现

### 5.1 常见日志特征

文件上传漏洞在日志中可能出现以下特征：

- 请求方法为 POST；
- 请求头中出现 `multipart/form-data`；
- 上传文件后缀异常，例如 `.php`、`.jsp`、`.asp`、`.aspx`、`.phtml`；
- 上传后很快访问上传目录中的文件；
- 上传接口返回成功后，访问路径出现 `/uploads/`、`/upload/`、`/files/`；
- 上传文件的 Content-Type 与文件后缀不匹配。

### 5.2 示例特征

```text
POST /dvwa/vulnerabilities/upload/ HTTP/1.1
Content-Type: multipart/form-data
filename="upload-test.php"
```

上传后访问：

```text
GET /dvwa/hackable/uploads/upload-test.php HTTP/1.1
```

### 5.3 告警建议

- 对高风险脚本后缀上传进行高危告警；
- 对上传成功后立即访问上传文件的行为进行关联分析；
- 对上传文件名包含双后缀、特殊字符、大小写绕过的情况进行检测；
- 对上传接口增加用户、IP、文件名、文件大小、MIME 类型记录。

### 5.4 误报控制

不要只看文件名后缀，还要结合上传接口、响应结果和后续访问行为。某些业务可能上传代码压缩包或文本文件，但上传后如果能通过 Web 路径直接访问并执行，风险明显升高。

## 6. 命令执行漏洞日志表现

### 6.1 常见日志特征

命令执行测试在日志中可能出现以下特征：

- 参数中出现命令连接符，例如 `&`、`&&`、`|`、`;`；
- URL 编码后出现 `%26`、`%7C`、`%3B`；
- 参数中出现系统命令关键字，例如 `whoami`、`id`、`cat`、`dir`、`type`、`ping`；
- 网络诊断、文件处理、备份压缩等功能点出现异常字符；
- 响应内容中出现系统用户名、目录列表、命令输出等信息。

### 6.2 示例特征

```text
ip=127.0.0.1+%26+whoami&Submit=Submit
```

其中 `%26` 是 `&` 的 URL 编码，表示追加执行命令。

### 6.3 告警建议

- 对命令连接符和系统命令关键字组合进行高危告警；
- 对网络诊断类接口中的非 IP 字符进行告警；
- 对响应内容中出现系统路径、用户名、命令输出的情况进行关联分析；
- 对命令执行测试频率较高的源 IP 进行聚合。

### 6.4 误报控制

单独出现 `ping`、`dir` 等字符串不一定是攻击，需要结合参数位置和命令连接符判断。比如帮助文档里出现命令名称可能是正常行为。

## 7. 目录遍历 / 任意文件读取日志表现

### 7.1 常见日志特征

目录遍历测试在日志中可能出现以下特征：

- URL 参数中出现 `../`；
- URL 编码中出现 `..%2f`、`%2e%2e%2f`；
- 参数中出现敏感文件路径，例如 `/etc/passwd`、`win.ini`、`.env`、`config.php`；
- 文件包含、文件下载、模板加载等接口出现异常路径；
- 同一 IP 对多个路径进行尝试。

### 7.2 示例特征

```text
/dvwa/vulnerabilities/fi/?page=../../hackable/uploads/read-test.txt
```

### 7.3 告警建议

- 对 `../` 和其编码形式进行告警；
- 对敏感文件名访问进行高危告警；
- 对文件读取类接口中的异常路径进行重点监控；
- 对同一 IP 多次变换路径的行为进行聚合分析。

### 7.4 误报控制

某些前端资源路径可能正常包含 `../`，例如静态资源引用。但如果 `../` 出现在用户可控参数中，尤其是文件读取、下载、包含类接口中，应提高风险等级。

## 8. 弱口令 / 暴力破解日志表现

### 8.1 常见日志特征

弱口令和暴力破解在日志中可能出现以下特征：

- 同一 IP 短时间内多次访问登录接口；
- 同一账号连续多次登录失败；
- 同一 IP 尝试多个账号；
- 多次登录失败后出现一次登录成功；
- User-Agent 异常、为空或高度一致；
- 请求间隔固定，疑似工具自动化尝试。

### 8.2 示例特征

```text
GET /dvwa/vulnerabilities/brute/?username=admin&password=123456&Login=Login
GET /dvwa/vulnerabilities/brute/?username=admin&password=password&Login=Login
```

### 8.3 告警建议

- 对同一账号连续失败设置阈值告警；
- 对同一 IP 尝试多个账号进行撞库告警；
- 对短时间失败后成功登录提高风险等级；
- 对管理员账号登录失败设置更低告警阈值；
- 记录登录结果、账号、来源 IP、User-Agent 和时间。

### 8.4 误报控制

用户忘记密码也可能多次登录失败，因此应结合失败次数、账号数量、来源 IP、时间窗口、User-Agent 和是否最终成功登录进行判断。

## 9. 越权漏洞日志表现

### 9.1 常见日志特征

越权漏洞在日志中可能出现以下特征：

- 同一登录用户访问多个不同用户 ID；
- 同一 IP 高频枚举资源 ID；
- URL 中的 `user_id`、`uid`、`username`、`order_id` 等参数频繁变化；
- 普通用户访问管理员接口；
- 访问结果状态码多为 200，但业务上不应允许访问；
- 访问资源的归属用户与当前登录用户不一致。

### 9.2 示例特征

```text
/pikachu/vul/overpermission/op1/op1_mem.php?username=lili&submit=...
```

当前登录用户如果不是 `lili`，但能访问 `lili` 的资料，就属于异常访问。

### 9.3 告警建议

- 对同一用户短时间访问多个用户资源进行行为分析；
- 对普通用户访问管理接口进行告警；
- 对资源 ID 连续递增、递减访问进行枚举检测；
- 应用日志中记录当前登录用户、目标资源 ID、资源归属用户和访问结果。

### 9.4 误报控制

管理员、客服、审核员等角色可能正常访问多个用户资源。因此越权日志分析必须结合用户角色、权限范围和业务场景判断。

## 10. SSRF 日志表现

### 10.1 常见日志特征

SSRF 测试在日志中可能出现以下特征：

- URL 参数中出现完整 URL；
- 参数中出现 `127.0.0.1`、`localhost`、`0.0.0.0`；
- 参数中出现内网地址，例如 `10.x.x.x`、`172.16.x.x`、`192.168.x.x`；
- 参数中出现云元数据地址；
- 远程资源抓取、URL 预览、图片加载、Webhook 测试等功能点出现异常目标；
- 服务端出站请求日志中出现访问内网地址的记录。

### 10.2 示例特征

```text
/pikachu/vul/ssrf/ssrf_curl.php?url=http://127.0.0.1/pikachu/
```

### 10.3 告警建议

- 对 URL 参数中的本机地址和内网地址进行高危告警；
- 对云元数据地址进行高危告警；
- 对 URL 预览、远程图片加载、Webhook 等接口重点监控；
- 记录服务端出站请求目标域名、解析 IP、响应状态码和耗时；
- 对重定向后的最终 IP 也进行安全校验。

### 10.4 误报控制

部分内部系统可能确实需要访问内网服务，因此应结合业务白名单判断。但普通用户可控 URL 参数中出现本机地址、内网地址或云元数据地址，应默认视为高风险行为。

## 11. CSRF 日志表现

### 11.1 常见日志特征

CSRF 在日志中可能出现以下特征：

- 敏感操作请求缺少 CSRF Token；
- 修改资料、修改密码、绑定邮箱等接口由 GET 请求触发；
- 请求带有合法 Cookie，但 Referer 为空或来自非本站域名；
- Origin 请求头异常或缺失；
- 同一用户短时间内出现异常资料变更；
- 用户没有明显访问修改页面，但出现了修改提交请求。

### 11.2 示例特征

```text
GET /pikachu/vul/csrf/csrfget/csrf_get_edit.php?sex=boy&phonenum=19999999999&add=csrf_attack_test&email=csrf@test.com&submit=submit
Cookie: PHPSESSID=***
```

### 11.3 告警建议

- 对敏感操作接口缺少 CSRF Token 的请求进行告警；
- 对 GET 请求触发修改类操作进行安全审计；
- 对异常 Referer 或 Origin 的敏感操作请求进行告警；
- 对修改手机号、邮箱、密码、地址等高风险操作记录详细日志；
- 对短时间内频繁修改用户资料的行为进行告警。

### 11.4 误报控制

Referer 为空不一定就是攻击，部分浏览器隐私设置、收藏夹访问或代理环境可能导致 Referer 缺失。更可靠的方式是结合 CSRF Token、请求方法、操作类型、用户身份、来源页面和行为频率进行综合判断。

## 12. XXE 日志表现

### 12.1 常见日志特征

XXE 在日志中可能出现以下特征：

- XML 请求体中出现 `DOCTYPE`；
- XML 请求体中出现 `ENTITY`；
- XML 请求体中出现 `SYSTEM`；
- XML 请求体中出现 `file://`；
- XML 接口中出现异常 DTD 定义；
- 请求参数或请求体中出现本地文件路径；
- XML 接口响应长度异常；
- 服务端出站请求日志中出现由 XML 解析触发的外部请求。

### 12.2 示例特征

```text
POST /pikachu/vul/xxe/xxe_1.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

xml=<?xml version="1.0"?>
<!DOCTYPE note [
<!ENTITY xxe SYSTEM "file:///C:/data/phpstudy_pro/WWW/pikachu/xxe-test.txt">
]>
<name>&xxe;</name>
&submit=提交
```

### 12.3 告警建议

- 对 XML 接口中出现 `DOCTYPE`、`ENTITY`、`SYSTEM`、`file://` 的请求进行告警；
- 对 SOAP、SAML、XML 文件导入等接口进行重点监控；
- 对 XML 请求体中的本地文件路径和内网地址进行高危告警；
- 对异常响应长度变化进行关联分析；
- 对服务端异常出站请求进行监控；
- 对同一 IP 高频提交异常 XML 的行为进行聚合告警。

### 12.4 误报控制

部分合法 XML 文档可能包含 DTD，因此不能只根据 `DOCTYPE` 单独判定为攻击。更可靠的方式是结合是否存在外部实体、是否指向本地文件或内网地址、接口功能、用户身份、响应内容变化和服务端出站请求行为进行综合判断。

## 13. PHP 反序列化日志表现

### 13.1 常见日志特征

PHP 反序列化风险在日志中可能出现以下特征：

- 请求参数中出现 PHP 序列化对象格式，例如 `O:1:"S"`；
- 参数中出现 `s:长度:"内容"`、`a:数量:{...}` 等序列化结构；
- 请求中出现异常类名或异常对象属性；
- 反序列化失败导致异常提示或 500 响应；
- 参数中同时出现脚本标签、文件路径、命令关键字等异常内容；
- 同一 IP 多次提交不同序列化对象进行测试。

### 13.2 示例特征

```text
POST /pikachu/vul/unserilization/unser.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

o=O:1:"S":1:{s:4:"test";s:29:"<script>alert('xss')</script>";}
```

### 13.3 告警建议

- 对用户输入参数中出现 `O:\d+:"`、`s:\d+:"`、`a:\d+:{` 等序列化特征进行告警；
- 对接口中出现异常对象结构的请求进行记录；
- 对反序列化失败、异常类名、异常属性进行应用日志记录；
- 对反序列化参数中同时包含脚本标签、文件路径或命令关键字的请求提高风险等级；
- 对同一 IP 高频提交不同序列化对象的行为进行聚合告警。

### 13.4 误报控制

部分系统可能正常使用序列化数据，例如缓存、会话、内部接口等。因此不能仅凭 `O:` 或 `s:` 判定攻击，应结合参数来源、接口功能、是否用户可控、类名是否异常、响应状态码和访问频率综合判断。

## 14. 综合告警思路

单条日志通常只能说明存在可疑行为，不能直接证明完整攻击链。更可靠的方式是进行关联分析。

### 14.1 按源 IP 聚合

观察同一源 IP 是否在短时间内测试多个漏洞类型，例如先测试 SQL 注入，再测试 XSS、目录遍历和文件上传。

### 14.2 按账号聚合

观察同一账号是否访问了大量不属于自己的资源，或者是否出现异常登录、异常下载、异常修改行为。

### 14.3 按接口聚合

观察某个接口是否频繁出现异常参数、异常状态码或异常响应大小。

### 14.4 按时间窗口聚合

设置 1 分钟、5 分钟、15 分钟等时间窗口，统计异常请求数量、失败登录次数、不同参数数量和不同目标资源数量。

### 14.5 按攻击链聚合

例如文件上传风险可以关联：

1. 上传 `.php` 文件；
2. 服务端返回上传成功；
3. 短时间内访问上传目录中的 `.php` 文件；
4. 响应内容异常或出现命令执行痕迹。

这种关联比单独检测文件后缀更准确。

## 15. 与 LogForenSight 项目的联动思路

本项目可以与日志分析项目形成联动：

1. Web 漏洞复现项目提供攻击行为样本；
2. 日志分析项目解析 access.log；
3. 根据 SQL 注入、XSS、目录遍历、暴力破解等特征生成风险标签；
4. 对同一 IP、同一接口、同一账号的异常行为进行聚合；
5. 输出风险摘要、证据片段和修复建议；
6. 形成从漏洞复现到日志检测再到安全运营研判的闭环。

联动后的能力链路为：

```text
漏洞复现 -> Burp 请求分析 -> 访问日志特征 -> 告警规则 -> 安全运营研判 -> 报告输出
```

## 16. 总结

Web 攻击日志分析不能只依赖单个关键字匹配，应结合请求路径、参数位置、HTTP 方法、状态码、响应大小、访问频率、账号身份和业务权限进行综合判断。

本速查表用于帮助将漏洞复现行为转化为安全运营检测思路，提升从漏洞验证到日志研判的完整安全分析能力。
