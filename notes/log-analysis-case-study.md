# Web 攻击日志分析案例

## 1. 分析目标

本案例基于 `sample-logs/access-demo.log`，模拟 Web 攻击访问日志分析过程，识别 SQL 注入、XSS、文件上传、命令执行、目录遍历、弱口令尝试、水平越权、SSRF、CSRF、XXE、PHP 反序列化、目录扫描和敏感路径访问等风险特征。

本案例的目标不是证明日志中的每一条请求都一定构成漏洞，而是展示如何从访问日志中提取可疑行为，并结合 URI、参数、状态码、响应大小、User-Agent 和业务上下文进行人工研判。

## 2. 分析流程

1. 使用 `access-log-risk-summary.py` 读取访问日志；
2. 生成 Markdown 风险摘要；
3. 查看 Top IP 和高频请求来源；
4. 查看命中的风险类型；
5. 结合请求 URI、参数、状态码、响应大小和 User-Agent 进行人工复核；
6. 输出研判结论和处置建议。

执行命令：

```text
python tools\access-log-risk-summary.py sample-logs\access-demo.log -o summary\log-risk-summary.md
```

## 3. 发现结果

| 风险类型 | 日志证据 | 研判结论 | 处置建议 |
|---|---|---|---|
| SQL 注入 | 参数中出现单引号、`OR`、`UNION SELECT` 等特征 | 疑似 SQL 注入测试 | 使用参数化查询，记录异常参数并配置告警 |
| XSS | 参数中出现 `script`、`onerror` 等特征 | 疑似 XSS 探测 | 输出编码，启用 CSP，记录高危输入 |
| 文件上传 | 出现上传接口访问和上传文件访问 | 疑似文件上传链路测试 | 限制文件类型，上传目录禁止脚本执行 |
| 命令执行 | 参数中出现 `whoami`、命令连接符等特征 | 疑似命令执行测试 | 禁止拼接系统命令，使用白名单参数 |
| 目录遍历 | 参数中出现 `../`、敏感路径读取尝试 | 疑似任意文件读取测试 | 限制文件包含路径，规范化路径校验 |
| 弱口令尝试 | 登录接口短时间多次请求 | 疑似弱口令或暴力破解尝试 | 限速、验证码、账号锁定、多因素认证 |
| 水平越权 | 同一接口通过参数访问不同用户资源 | 疑似资源归属校验不足 | 服务端校验当前用户是否有权访问目标资源 |
| SSRF | 参数中出现 `127.0.0.1`、`file://` 等目标 | 疑似服务端请求伪造测试 | 限制目标协议和地址，禁止访问内网和本地地址 |
| CSRF | GET 请求修改用户资料参数 | 疑似跨站请求伪造风险 | 使用 CSRF Token，关键操作使用 POST 并校验来源 |
| XXE | 请求特征中出现 `SYSTEM`、`file` 等 XML 外部实体线索 | 疑似 XXE 测试 | 禁用外部实体解析，使用安全 XML 解析配置 |
| PHP 反序列化 | 请求中出现序列化对象特征 `O:` | 疑似不安全反序列化测试 | 避免反序列化用户输入，使用安全数据格式 |
| 目录扫描 | 大量访问 `.git`、`.env`、`README.md` 等路径 | 疑似目录枚举或敏感路径扫描 | 关闭敏感文件暴露，配置访问控制和扫描告警 |

## 4. 人工研判说明

日志命中风险特征不等于漏洞一定成立。安全分析时需要结合以下信息进行判断：

- 请求是否命中真实业务接口；
- 状态码是否为 `200`、`302`、`403`、`404`；
- 响应大小是否异常；
- 是否出现短时间高频访问；
- User-Agent 是否显示工具特征；
- 请求参数是否包含明显攻击 Payload；
- 是否存在登录态、权限关系和业务上下文。

例如，`dirsearch` 或 `Nuclei` 的 User-Agent 可以说明请求来自工具扫描，但工具命中结果仍需要人工复核。`SQLmap` 相关请求可以说明存在自动化注入测试行为，但是否构成真实漏洞，需要结合页面响应、数据库报错和手工验证结果判断。

## 5. 与漏洞复现的关系

本项目先在 DVWA 和 Pikachu 中完成漏洞复现，再将典型攻击请求抽象为访问日志样例，最后通过 Python 脚本生成风险摘要。

这形成了一个基础闭环：

```text
漏洞复现 -> 攻击请求 -> 访问日志 -> 风险识别 -> 人工研判 -> 修复建议
```

## 6. 小结

本案例展示了如何把 Web 漏洞复现结果转化为日志分析场景。相比单纯记录 Payload，日志分析更关注攻击行为在访问日志中的表现形式，以及如何通过规则、脚本和人工研判发现潜在风险。

后续可以将该样例日志导入 LogForenSight 等日志分析工具，继续完成事件聚合、风险类型识别、调查实体提取和证据包输出。
