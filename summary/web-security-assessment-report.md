# Web 系统安全评估模拟报告

## 1. 测试说明

### 1.1 项目背景

本报告基于本地授权靶场环境，对常见 Web 安全漏洞进行模拟安全评估。测试对象包括 DVWA 和 Pikachu 两个本地靶场系统，测试内容覆盖 SQL 注入、XSS、文件上传、命令执行、目录遍历、弱口令、水平越权、SSRF、CSRF 等常见 Web 漏洞类型。

本次测试仅用于安全学习、漏洞理解、报告编写和安全服务交付训练，不涉及真实业务系统、公网目标、第三方系统或任何未授权测试。

### 1.2 测试目标

本次测试目标包括：

* 识别常见 Web 漏洞的触发条件；

* 使用 Burp Suite 对关键请求进行抓包分析；

* 验证漏洞是否可以被手工复现；

* 分析漏洞可能造成的安全影响；

* 给出对应的修复建议；

* 形成标准化安全评估报告。

所有测试均在本地授权靶场环境中完成，测试目标为学习环境中的 DVWA 和 Pikachu，不涉及任何真实业务系统或未授权目标。

## 2. 测试方法

本次测试主要采用手工验证方式，结合 Burp Suite 进行 HTTP 请求分析。

测试流程如下：

1. 搭建本地靶场环境；

2. 识别目标功能点；

3. 使用浏览器进行正常业务访问；

4. 使用 Burp Suite 抓取请求；

5. 修改关键参数并进行漏洞验证；

6. 保存页面截图和 Burp 请求截图；

7. 分析漏洞原理和风险影响；

8. 编写修复建议和复测结论。

## 4. 高危漏洞详情

### 4.1 SQL 注入

SQL 注入漏洞出现在 DVWA 的 SQL Injection 模块。测试中，正常输入 `1` 时仅返回单个用户信息；输入单引号时触发 SQL 报错；输入 `1' OR '1'='1` 后页面返回多条用户记录，说明用户输入改变了后端 SQL 查询逻辑。

风险影响包括未授权查询数据库内容、敏感信息泄露、绕过认证、数据篡改等。

修复建议包括使用参数化查询、预编译语句、输入类型校验、关闭详细 SQL 错误回显、数据库最小权限和异常查询日志告警。

单点报告详见：

`reports/01-sql-injection.md`

### 4.2 文件上传漏洞

文件上传漏洞出现在 DVWA 的 File Upload 模块。测试中，服务端允许上传 `.php` 文件，并且上传后的文件可以通过 Web 路径访问执行，说明服务端未严格限制文件类型和上传目录执行权限。

风险影响包括上传恶意脚本、服务器执行非预期代码、进一步读取或修改服务器文件等。

修复建议包括文件类型白名单、MIME 类型校验、文件内容校验、上传文件重命名、上传目录禁止脚本执行、上传文件存储到 Web 根目录之外、上传日志记录和告警。

单点报告详见：

`reports/03-file-upload.md`

### 4.3 命令执行漏洞

命令执行漏洞出现在 DVWA 的 Command Injection 模块。测试中，正常输入 `127.0.0.1` 时页面返回 ping 结果；输入 `127.0.0.1 & whoami` 后页面额外返回当前系统用户信息，说明额外系统命令被执行。

风险影响包括执行非预期系统命令、获取服务器信息、读取或修改文件、进一步扩大攻击影响等。

修复建议包括避免调用系统 Shell、优先使用安全 API、输入白名单校验、禁止命令连接符、使用低权限账号运行 Web 服务、记录异常命令行为。

单点报告详见：

`reports/04-command-injection.md`

### 4.4 目录遍历 / 任意文件读取

目录遍历漏洞出现在 DVWA 的 File Inclusion 模块。测试中，通过 `page=../../hackable/uploads/read-test.txt` 成功读取自己创建的无害测试文件，说明服务端未限制文件读取路径范围。

风险影响包括读取非预期文件、泄露配置文件、日志文件、源码文件、密钥或 Token 等敏感信息。

修复建议包括不直接使用用户传入路径、使用文件 ID 映射真实路径、设置文件白名单、路径规范化、限制读取根目录、最小权限和异常路径访问告警。

单点报告详见：

`reports/05-directory-traversal.md`

### 4.5 水平越权漏洞

水平越权漏洞出现在 Pikachu 的 Over Permission 模块。测试中，当前登录用户为 `lucy`，修改请求参数 `username=lili` 后，可以查看 `lili` 的个人信息，说明服务端没有进行资源级权限校验。

风险影响包括用户资料泄露、查看或操作他人订单、地址、文件、工单等资源。

修复建议包括服务端权限校验、从 Session 或 Token 获取当前用户身份、资源归属校验、管理员接口单独校验权限、异常访问日志告警。

单点报告详见：

`reports/07-access-control.md`

### 4.6 SSRF 服务端请求伪造

SSRF 漏洞出现在 Pikachu 的 SSRF(curl) 模块。测试中，将 `url` 参数修改为 `http://127.0.0.1/pikachu/` 后，页面返回 Pikachu 首页内容，说明服务端会根据用户传入的 URL 发起请求。

风险影响包括访问服务器本机服务、探测内网资源、访问内部接口、在云环境中访问云元数据服务等。

修复建议包括 URL 白名单、协议限制、禁止访问本机和内网地址、DNS 解析后 IP 校验、重定向校验、请求超时和响应大小限制、异常 URL 请求日志告警。

单点报告详见：

`reports/08-ssrf.md`

## 5. 中危漏洞详情

### 5.1 XSS 跨站脚本漏洞

XSS 漏洞出现在 DVWA 的 XSS Reflected 和 XSS Stored 模块。测试中，反射型 XSS 通过 `name` 参数触发脚本执行；存储型 XSS 通过留言板提交脚本内容，刷新页面后仍会触发弹窗，说明脚本内容被保存并再次输出到页面。

风险影响包括在用户浏览器中执行恶意 JavaScript、篡改页面内容、构造伪造表单、在用户登录状态下发起非预期请求等。

修复建议包括输出编码、输入校验、富文本安全清洗、设置 Content Security Policy、设置 HttpOnly 和 SameSite Cookie、避免危险 DOM API。

单点报告详见：

`reports/02-xss.md`

### 5.2 弱口令 / 暴力破解

弱口令风险出现在 DVWA 的 Brute Force 模块。测试中，错误密码登录失败，默认弱口令 `admin/password` 登录成功，且 Low 模式下没有明显验证码、锁定或限速机制。

风险影响包括账号被接管、后台被未授权访问、用户隐私泄露、批量撞库或密码喷洒攻击等。

修复建议包括禁用默认密码、强密码策略、弱密码字典检测、失败次数限制、IP 限速、验证码、多因素认证、登录日志和异常告警。

单点报告详见：

`reports/06-weak-password.md`

### 5.3 CSRF 跨站请求伪造

CSRF 漏洞出现在 Pikachu 的 CSRF(get) 模块。测试中，用户 lucy 已经处于登录状态，访问构造好的 GET 请求链接后，个人资料中的手机号、住址和邮箱被修改为攻击者指定的测试值。

该问题说明服务端仅依赖浏览器自动携带的 Cookie 判断用户身份，但没有校验 CSRF Token，也没有确认该请求是否来自用户真实操作意愿。

风险影响包括修改用户资料、修改绑定邮箱或手机号、诱导用户提交订单、删除数据，管理员登录状态下还可能导致后台配置被修改。

修复建议包括对敏感操作增加 CSRF Token、避免使用 GET 请求执行修改类操作、校验 Origin / Referer、设置 SameSite Cookie，并对高风险操作增加二次确认或重新认证。

单点报告详见：

`reports/09-csrf.md`

## 6. 整体风险分析

本次测试覆盖了输入校验、输出编码、文件处理、命令调用、路径控制、身份认证、访问控制和服务端请求控制等多个 Web 安全关键面。

整体来看，高风险问题主要集中在以下方面：

1. 服务端过度信任用户输入；

2. 关键功能缺少严格白名单校验；

3. 权限控制没有落实到服务端资源级校验；

4. 文件上传和文件读取缺少边界限制；

5. 服务端请求外部资源时没有限制目标地址；

6. 登录接口缺少失败限制、锁定和告警机制；
7. 敏感操作缺少 CSRF Token 校验和请求来源校验机制。

这些问题在真实业务系统中可能导致数据泄露、账号接管、服务器被进一步控制或内部资源暴露等风险。

## 7. 整改建议

建议从以下方面进行整体整改：

1. 所有数据库查询使用参数化查询或预编译语句；

2. 所有用户输入在输出到页面前进行上下文相关编码；

3. 文件上传功能使用白名单、内容校验和上传目录执行限制；

4. 避免直接拼接系统命令，优先使用安全 API；

5. 文件读取功能使用文件 ID 映射，限制读取目录范围；

6. 登录接口增加失败次数限制、验证码、账号锁定和日志告警；

7. 所有用户资源访问都必须做服务端资源归属校验；

8. 服务端请求外部 URL 时使用白名单、协议限制和内网地址拦截；

9. 对异常请求、攻击特征、登录失败、越权访问等行为记录日志；

10. 建立复测机制，确认修复后漏洞不可继续复现。

## 8. 安全运营视角

从安全运营角度看，本次复现的漏洞在访问日志中可能表现为以下特征：

| 漏洞类型 | 日志表现 | 告警建议 |
|---|---|---|
| SQL 注入 | 参数中出现单引号、OR、UNION、SELECT、注释符等特征 | 对 SQL 关键字组合、异常状态码、异常响应长度进行告警 |
| XSS | 参数中出现 `<script>`、事件属性、HTML 标签等内容 | 对脚本标签、危险事件属性、编码绕过特征进行告警 |
| 文件上传 | 上传接口出现非预期后缀，例如 `.php`、`.jsp`、`.asp` | 对高风险后缀上传和上传后访问行为进行关联分析 |
| 命令执行 | 参数中出现 `&`、`&&`、`&#124;`、`;`、命令关键字 | 对命令连接符和系统命令关键字进行告警 |
| 目录遍历 | URL 中出现 `../`、`..%2f`、敏感文件名 | 对目录跳转和敏感文件访问路径进行告警 |
| 暴力破解 | 同一 IP 短时间多次访问登录接口并失败 | 对连续失败、失败后成功、多账号尝试进行聚合告警 |
| 越权漏洞 | 同一用户频繁访问不同用户 ID 或资源 ID | 对 ID 枚举、资源访问异常跨度进行行为分析 |
| SSRF | URL 参数中出现 `127.0.0.1`、`localhost`、内网地址 | 对本机地址、内网地址、云元数据地址请求进行告警 |
| CSRF | 敏感操作请求缺少 Token，Referer 或 Origin 异常，GET 请求触发资料修改 | 对缺少 Token 的敏感操作、异常来源请求、GET 修改类操作进行告警 |

## 9. 复测结论

本次测试为本地靶场环境中的模拟安全评估。单点漏洞报告中已经通过 Low 与 Impossible 模式对比、页面结果对比、Burp 请求分析等方式验证了漏洞存在及修复思路。

真实业务系统整改后，应进行以下复测：

1. 原始漏洞 payload 是否失效；

2. 服务端是否返回合理错误提示；

3. 是否仍然能通过编码、大小写、重定向等方式绕过；

4. 日志是否记录异常请求；

5. 告警规则是否能够识别对应攻击行为。

## 10. 总结

本次项目完成了 9 类常见 Web 漏洞的本地授权靶场复现、原理分析、Burp 抓包验证、风险影响分析、修复建议和复测结论整理。

该项目的主要价值不只是漏洞复现本身，而是通过统一报告格式，将漏洞验证、风险评估、修复建议和安全运营日志视角结合起来，形成接近安全服务交付的项目材料。
