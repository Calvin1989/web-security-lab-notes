# Web Security Lab Notes 项目复盘

## 1. 项目定位

本项目基于 DVWA、Pikachu 等本地授权靶场，围绕常见 Web 漏洞完成复现、抓包分析、风险说明、修复建议和复测整理。

项目重点不是单纯记录 Payload，而是把漏洞验证过程整理成接近安全服务交付的材料：每个结论尽量保留请求证据、响应结果、风险判断和整改建议。

## 2. 实践范围

项目覆盖以下 11 类常见 Web 漏洞：

- SQL 注入
- XSS
- 文件上传
- 命令执行
- 目录遍历 / 任意文件读取
- 弱口令 / 暴力破解
- 水平越权
- SSRF
- CSRF
- XXE
- PHP 反序列化

所有测试均限定在本地授权环境中完成，不涉及真实业务系统或公网目标。

## 3. 技术路线

### 3.1 手工验证为主

漏洞验证主要通过页面响应、参数变化和 Burp Suite 抓包完成。工具结果只作为辅助信息，不直接等同于漏洞结论。

### 3.2 证据链整理

每类漏洞尽量保留以下材料：

- 正常请求或正常业务结果
- 漏洞触发请求或异常响应
- Burp Suite 关键请求证据
- 风险影响说明
- 修复建议
- 修复后复测或安全配置对比

### 3.3 工具辅助复核

项目补充了 Nmap、dirsearch、SQLmap、Nuclei 的基础使用记录，用于展示安全评估中常见的信息收集、目录枚举、辅助验证和模板扫描结果复核流程。

## 5. 关键收获

1. 漏洞判断需要结合请求参数、响应差异、权限关系和业务上下文，不能只依赖工具扫描结果。
2. Burp Suite 抓包证据可以把页面现象转化为可复核的 HTTP 请求链路。
3. SQLmap、Nuclei 等工具适合辅助验证和初筛，但需要人工确认漏洞是否真实成立。
4. 修复建议需要回到根因，例如参数化查询、输出编码、上传目录权限控制、服务端鉴权和内网访问限制。
5. 日志分析可以把漏洞复现中的攻击特征转化为检测规则和安全运营研判思路。

## 6. 后续优化方向

- 补充更多真实报告中的风险评级依据和影响范围描述。
- 增加修复前后差异截图或配置对比。
- 扩展日志样本，加入更多状态码、User-Agent、时间窗口和攻击链关联分析。
- 对工具扫描结果增加误报样例和人工复核记录。
- 持续保持截图、Cookie、路径和本地用户名等信息的脱敏处理。
